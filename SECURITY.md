# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 0.1.x | прототип: исправления безопасности принимаются, обратной совместимости нет |
| < 0.1 | не существует |

## Как сообщить об уязвимости

Используйте **Private vulnerability reporting** (вкладка Security → Report a
vulnerability) — не создавайте публичный issue для уязвимостей.

Ожидаемый срок первого ответа: 7 дней. Прототип, но правила честные.

## Область проекта (что ДОМОВОЙ делает и чего не делает)

ДОМОВОЙ изменяет только локальные, документированные настройки Windows
(реестр, службы, политики) от имени администратора, который сам это запустил.

Проект **не** содержит и никогда не будет содержать:
- загрузку и запуск внешних скриптов/бинарников во время применения твиков;
- скрытые сетевые соединения (сетевой контур отсутствует полностью);
- обфускацию, упаковщики, анти-отладку (прямой урок из кейс-стади Modern Tweaker);
- «тихую» очистку журналов без записи факта в собственный Ledger.

## Правила обращения с секретами (для контрибьюторов)

1. Никогда не коммитить токены, PAT, ключи, пароли — ни в код, ни в тесты, ни в документацию.
2. GitHub secret scanning автоматически отзывает скомпрометированные токены;
   утечкой считается и отправка токена в чат/скриншот/issue — такой токен
   немедленно перевыпускается.
3. Секреты передаются только через переменные окружения или GitHub Secrets.
4. Если токен попал куда-либо кроме переменной окружения — отозвать немедленно и создать новый.

## Известные ограничения (честно, на прототипе)

- Undo восстанавливает значения из снимка; удаление ключа реестра, созданного
  твиком, при undo — в v0.2 (см. `docs/spec.md`, §9).
- Точка восстановления Windows создаётся не чаще раза в 24 часа (ограничение ОС);
  модуль обходит это мягко и фиксирует факт в Ledger.
