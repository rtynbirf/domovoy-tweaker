## [1.6.0] — 2026-11-04

### Added
- **Продакшн-эргономика GUI (async, ошибки, права, поиск)** — ревизия по
  чеклисту десктоп-релизов (Microsoft Learn: thread-safe WinForms calls,
  UX checklist, SmartScreen reputation — см.
  `docs/analysis/release-practices-audit.md`):
  - **UI больше не замерзает**: каждое действие уходит в фоновый
    ранспейс PowerShell (свежая сессия, сама импортирующая модуль);
    результат возвращается через синхронизированную очередь, которую
    UI-таймер (150 мс) выгружает в окно вывода. Раньше `Apply`/cleanup
    блокировали UI-поток — окно падало в «(Не отвечает)» на долгих
    операциях. Тонкий клиент не тронут: воркер исполняет ровно ту же
    CLI-строку.
  - **Кнопка «Стоп»** в статус-баре: `PowerShell.Stop()` останавливает
    выполняющийся пайплайн, состояние честно показывается («Отмена…» →
    «Отменено.»).
  - **Глобальный перехват ошибок**: `Application.ThreadException` в
    режиме `CatchException` + обработчик `AppDomain.UnhandledException`
    — любая необработанная ошибка UI-потока теперь показывает читаемый
    диалог («скопировать подробности» в буфер) и пишет технический журнал
    в `%LOCALAPPDATA%\Domovoy\logs\domovoy-gui-<дата>.log`. JIT-диалог
    отладчика из пользовательского отчёта больше недостижим на этом пути.
  - **Статус-бар с правами и элевацией**: текущая операция,
    «Права: администратор / обычный сеанс», версия; в не-админской
    сессии — кнопка «Перезапустить от администратора…» (UAC, через
    `domovoy.ps1 Show-Domovoy`), вместо молчаливых access denied от
    HKLM/служб.
  - **Поиск по каталогу**: фильтр по Id/Title/Risk сужает список живьём,
    счётчик «Показано: N из M».
  - **Идентичность продукта**: иконка приложения (домовой-домик,
    `src/Domovoy/domovoy.ico`, 16–256 px) в окне и в exe; VERSIONINFO
    (название, версия 1.6.0.0, автор, копирайт) теперь читается в
    свойствах exe Explorer'ом, виден в SmartScreen/winget/AV-эвристиках.
  - `EnableVisualStyles` (тематические контролы вместо Win95) и
    DPI-awareness (чёткий рендер на масштабированных дисплеях).

### Changed
- **Портативный exe: запуск GUI без единого окна консоли** — двойной клик
  скрывает консоль лаунчера сразу после подготовки payload и стартует
  движок с `CreateNoWindow=true` и `-WindowStyle Hidden`; лаунчер
  завершается, GUI живёт самостоятельным процессом. Раньше поверх GUI
  висело чёрное окно-баннер лаунчера на всё время сессии плюс свёрнутая
  консоль движка. Режимы сохранены: аргументы форвардятся CLI-шиму
  дословно (видимая консоль, как и раньше), `--wait` возвращает прежнее
  блокирующее поведение для CI/диагностики, `--selftest`/`--extract`
  без изменений.
- **Фатальные ошибки GUI-старта видны**: `domovoy.ps1` в режиме
  `Show-Domovoy` оборачивает запуск в try/catch — при падении импорта
  модуля показывается диалог (двуязычный) с путём к журналу
  `%LOCALAPPDATA%\Domovoy\logs\domovoy-fatal-*.log` вместо молча
  исчезнувшего окна.
- **`--selftest` проверяет метаданные версии**: сверка
  `AssemblyInformationalVersion` сборки с версией payload — рассинхрон
  версии exe и модуля невозможен ни на CI, ни в песочнице.
- Сборщики (`tools/Build-PortableExe.ps1`, песочный драйвер) получили
  гейт дрейфа версий «манифест ≠ AssemblyInfo» и встройку иконки
  (`/win32icon` на CI; песочница — сгенерированный Win32 `.res`).

### Fixed
- Коллизия порядка инициализации замыканий в GUI: `GetNewClosure()`
  захватывает только уже существующие локальные переменные — поздние
  ссылки на кнопки/список/стоп выведены через хэш `$state` (рефакторинг
  v1.6.0, зафиксирован комментарием «closure discipline» в
  `Show-Domovoy.ps1`).

### Tests
- `tests/Domovoy.V07.Tests.ps1`: асинхронный жизненный цикл (guard без
  выбора → busy → Drain → done → кнопки включены) и живой фильтр
  каталога; поверхность `Tag.Handlers/Drain/State/Status/Search`.
- `tests/Domovoy.Portable.Tests.ps1`: контракт идентичности (icon +

  AssemblyInfo.

## [1.5.4] — 2026-11-04

### Fixed
- **GUI: каждая кнопка падала с «Get-DomovoyStrings is not recognized»**
  (краш портативного exe v1.5.3: клик по любой кнопке —
  `Button.OnMouseUp → CommandNotFoundException` под Windows PowerShell
  5.1). Хендлеры кнопок связаны через `.GetNewClosure()` — это новый
  динамический модуль, чья цепочка поиска команд доходит только до
  глобального session state: публичные команды модуля там видны (шимы
  импортируют модуль `-Global`), а приватная таблица строк — нет.
  Локализация (v1.6 п.6) добавила вызовы `Get-DomovoyStrings` во все
  closure-хендлеры — и каждая кнопка стала миной; CI не ловил, потому
  что `-Preview` строит окно, но кнопки не нажимает. Фикс: module-bound
  мост `$stringsLive = { Get-DomovoyStrings }` (создан в scope модуля —
  приватная функция резолвится в его собственном session state),
  все closure-хендлеры зовут его через `&`; таблица по-прежнему
  читается живьём, смена языка работает. Механика доказана
  proof-харнессом (баг воспроизведён 1-в-1, мост верифицирован,
  публичные команды в closure — контроль), регресс закреплён кликовым
  тестом в `tests/Domovoy.V07.Tests.ps1` (`PerformClick()` по
  DryRun/Refresh/Changes на preview-форме — на коде до фикса падает).

## [1.5.3] — 2026-11-04

### Added
- **Портативный однофайловый `Domovoy-<версия>-Portable.exe`** — релиз
  вкладывает готовый exe: весь релизный payload (модуль + каталог
  манифестов + схемы + оба CLI-шима + README + LICENSE) встроен в один
  файл. Двойной клик — распаковка рядом с exe (или в
  `%LOCALAPPDATA%\Domovoy\app`, если каталог только для чтения) и запуск
  GUI (`Show-Domovoy`); аргументы командной строки форвардятся CLI-шиму
  `domovoy.ps1` дословно (правило тонкого клиента: лаунчер не добавляет
  никакой собственной логики — только распаковку и старт). Гарантии:
  `requestedExecutionLevel asInvoker` в манифесте, защита от path
  traversal при распаковке, маркер с SHA-256 payload (готовый payload не
  распаковывается повторно), `--selftest` (распаковка во временный
  каталог + обязательные файлы + сверка версии манифеста с версией
  payload), `--extract [каталог]` — распаковка без запуска. Исходник —
  `packaging/shim/DomovoyPortable.cs` (C#5, .NET Framework 4.5+, ноль
  внешних зависимостей); сборщик — `tools/Build-PortableExe.ps1`
  (машинный `csc.exe`); CI — release-джоб `portable-exe` собирает exe,
  гейтит selftest-ом и сквозным прогоном `Get-DomovoyLanguage` через exe
  и вкладывает `Domovoy-<версия>-Portable.exe` (+ `.sha256`) в релиз;
  контракт упаковки закреплён `tests/Domovoy.Portable.Tests.ps1`.
- **Локальный one-click прогон**: `DOMOVOY-ONECLICK.bat` в корне репо +
  `tools/Invoke-DomovoyLocalCI.ps1`. Двойной клик: клонирование/обновление
  локальной копии (`%USERPROFILE%\domovoy-tweaker`), установка Pester 5.7.1
  и PSScriptAnalyzer, зеркало CI — анализатор с гейтом Error, Pester
  (полный набор на pwsh 7; на Windows PowerShell 5.1 — те же
  5.1-безопасные сьюты, что в CI-ноге), JSON-схемы, верификация упаковки
  (гейт P0-1) — и локальная сборка `Domovoy-<версия>.zip` + `.sha256`
  по раскладке release.yml (включая exe-шим через `csc.exe`). Артефакты
  и логи — вне репозитория (`%LOCALAPPDATA%\Domovoy\`); система
  не меняется, права администратора не требуются.

## [1.5.2] — 2026-11-03

### Fixed
- **Portable-цель winget-манифеста снова исполнимая**: вердикт валидации
  winget-pkgs по PR [#469700](https://github.com/microsoft/winget-pkgs/pull/469700)
  показал, что `NestedInstallerType: portable` допускает ровно один тип
  файла — `.exe` (`s_AllowedPortableFiletypes` в ManifestValidation.cpp
  winget-cli; ошибка `InvalidPortableFiletype`). Прежняя цель
  `Domovoy/domovoy.ps1` не проходит content-валидацию никогда.
  - В пакет добавлен **компилируемый exe-шим**: `packaging/shim/DomovoyShim.cs`
    (C#-исходник в репо, компиляция — .NET Framework `csc.exe` на CI),
    который резолвит РЕАЛЬНЫЙ путь своего exe через `GetFinalPathNameByHandle`
    (winget portable запускает его через symlink из Links-каталога) и
    форвардит вызов `domovoy.ps1` рядом с собой — та же схема тонкого
    клиента, ноль собственной логики.
  - Манифест-цель: `Domovoy/domovoy.ps1` → `Domovoy/domovoy.exe`.
  - Доказательство в CI: новый шаг «Portable exe shim gate» компилирует шим,
    прогоняет его напрямую И через symlink (продакшен-путь winget) на каждый
    пуш; release-джоб `shim-exe` собирает exe один раз, и все упаковочные
    контуры (zip, подписанный zip, галерейный пакет) везут РОВНО этот файл.
- **Заголовки `yaml-language-server` в манифестах**: Validation.md
  winget-pkgs требует `# yaml-language-server: $schema=...` в каждом файле
  манифеста — у подаваемых манифестов их не было. Добавлены ака.ссылки на
  схемы 1.12.0.
- **ManifestVersion 1.9.0 → 1.12.0** во всех трёх шаблонах: спецификация,
  на которую ссылается валидатор winget-pkgs. Подъём сверен по JSON-схемам
  winget-cli и добавляет ровно одно новое обязательное поле — `DefaultLocale:
  en-US` в version-манифесте (в 1.9.0 его не было; поймано машинной
  валидацией против схемы 1.12.0 ещё до подачи); остальные требования для
  используемых полей идентичны. Заодно плейсхолдер суммы закавычен
  (`InstallerSha256: "__SHA256__"`), чтобы всецифровой хеш не распарсился
  YAML-ом числом.

### Changed
- `docs/distribution.md`: вердикт валидатора зафиксирован, схема подачи
  обновлена на v1.5.2 (exe-цель, заголовки, 1.12.0).

## [1.5.0] — 2026-11-03

### Added
- v1.6 п.6 исполнен: локализация EN/RU строк-таблицей (последний пункт v1.6,
  исполнимый без ключей владельца). Появились две публичные команды — 53-я
  `Get-DomovoyLanguage` и 54-я `Set-DomovoyLanguage`.
  - **Строки-таблица** (`Get-DomovoyStrings`, private): каждое пользовательское
    предложение GUI и сводок ключевых отчётов живёт в таблице, en/ru,
    паритет ключей машиной проверяется тестом. Файл с кириллицей — UTF-8
    с BOM: PowerShell 5.1 читает без-BOM UTF-8 через системную ANSI-кодовую
    страницу и исказил бы каждую русскую строку (тест гейтит BOM).
  - **Переключатель**: `Set-DomovoyLanguage -Language ru` действует немедленно
    и пишет `<store>\language.txt` (следующая сессия стартует на выбранном
    языке); `Get-DomovoyLanguage` честно отвечает, откуда взят язык —
    session / store / default. Это настройка модуля, а не состояние машины:
    контура dry-run/apply и записи в журнал у неё нет (инварианты I1–I7
    охраняют состояние системы, а не язык интерфейса), и это задокументировано.
  - **GUI**: окно строится на активном языке; кнопка Language в тулбаре
    переключает en/ru, пишет настройку и сообщает честно — надписи кнопок
    обновятся при переоткрытии окна, а динамические сообщения (CLI-префикс,
    ошибки, подтверждения) перечитывают таблицу на каждый вызов и меняются
    сразу. EN-формулировки не изменились ни на букву — дефолт совпадает
    с прежними релизами.
  - **Отчёт об изменениях** (`Get-DomovoyChangeReport`): человеческие
    сводки событий из строк-таблицы; имена событий и все машинные поля
    заморожены (spec §10).
  - Замороженные форматы (заголовки каталога, help CLI, машинные поля
    отчётов) остаются EN — их тексты часть документированного контракта
    (spec §10); локализуется презентационный слой.
- Наблюдаемость CI (правило «CI должен доказывать»): падение прогона
  публикует машиночитаемый отчёт (упавшие тесты, сообщения, диагностические
  матрицы из `Should -Because`) в ветку `ci-report` — факты читаются из
  простого клона, без доступа к логам Actions и без API-квоты.

### Носитель
- Релиз v1.5.0 несёт поверх v1.4.1 только локализацию и перевод счётчика
  публичных команд в тесте модуля на живое чтение манифеста (замороженный
  литерал «52» протух бы молча на первой же новой команде). Веха v1.4.1
  выпущена ОТДЕЛЬНЫМ тегом сразу после починки fallout третьего прогона
  (см. секцию ниже): размаскированные платформенные гейты, обе волны
  фоллаута, PSResourceGet, обновляемая справка, SHA-пин actions
  v7.0.1/v7.0.2. Это первый релиз, у которого гейт await-tests отработал
  на собственном теге: до починки run-51 CI был красным на каждом
  коммите вехи, и тегировать её было честно нельзя.
### Fixed
- Тест «exports exactly 52 public commands» читает число публичных команд
  из `Domovoy.psd1` (54 на v1.5.0) вместо замороженного литерала; нижняя
  граница (>50) остаётся гейтом от пустого экспорта.
- Гейт релиза await-tests выбирал `max_by(.id)` по ВСЕМ прогонам SHA: один
  пуш двух ссылок (main + тег) запускает два прогона одного коммита,
  concurrency-группа отменяет проигравший — и гейт получал отменённый
  дубль вместо зелёного прогона того же коммита, отказывая релизу,
  который уже заслужен (release run 15). Отменённые прогоны исключены из
  выбора; настоящий провал по-прежнему останавливает релиз намертво.
- `Get-DomovoyStrings` на дефолтной ветке (свежий стор, ни разу не заданный
  язык) доходил до `ContainsKey($null)` и бросал на PS 7.6 — прогон 54/55
  уронили GUI-preview (V07) и change-report (Loop), которые читают таблицу,
  никогда не задавая язык; сьют локализации это ветку не покрывал, потому
  что всегда задавал язык явно. Дефолт `'en'` применяется до поиска
  таблицы; добавлен регрессионный тест дефолтной ветки. Первая попытка
  фикса потеряла UTF-8 BOM при перезаписи файла — BOM-гейт сьюта поймал
  это до коммита; BOM возвращён.

  до `BeforeAll`, поэтому прежнее размещение делало «Windows-only» блоки этих

- **Fallout первого прогона** (предсказан ТЗ v1.4.1 п.2 и подтверждён красным
  CI от 2026-11-03):
  - `file.timestamp` — план печатал закреплённые штампы в культурно-зависимом
    виде (`01/15/2024 10:30:00` вместо ISO 8601 из манифеста):
    `ConvertFrom-Json` отдаёт DateTime, и интерполяция рендерила его через
    текущую культуру. План снова показывает мгновение в ISO 8601
    (`yyyy-MM-ddTHH:mm:ssZ`, инвариантная культура) — как требует схема
    `timestampValue` и как сравнивает probe (probe и undo сравнивали
    мгновения и потому не ломались). Чинено кодом, не тестом: контракт
    документа сильнее случайного формата.

  администратор), поэтому admin-тесты впервые реально исполнились — и это
  вскрыло вторую волну настоящего фоллаута (следующий пункт).
- **Fallout второго прогона** (те же admin-тесты, впервые исполнившиеся на
  elevated CI-раннере: 14 красных тестов разобраны до трёх причин):
  - **Производственный баг** `Register-DomovoyWatchdog -Apply`: сплат передавал
    `Register-ScheduledTask` параметр `LogonType`, которого у командлета нет
    (`LogonType` живёт в `New-ScheduledTaskPrincipal`) — реальный вызов падал
    ParameterBindingException на любой Windows-машине, но был спрятан мёртвым
    гейтом и моками. Чинено кодом: сплат приведён к валидному набору
    параметров. Документированное обещание («только пока вы залогинены, без
    сохранённых паролей») даёт сам дефолтный принципал
    `Register-ScheduledTask` (текущий пользователь, Interactive) — поведение
    не меняется, меняется исход: с «гарантированно падает» на «работает».
  - `Write-DomovoyLedgerEntry` теперь перед дописыванием гарантирует
    существование родительского каталога журнала средствами .NET
    (`Directory.CreateDirectory`): инвариант I1 «дописывание не падает»
    защищён кодом, а не надеждой, что каталог уже создан. Проявилось как
    `DirectoryNotFoundException` у 11 тестов V07 после утечки моков (ниже).
  - **Урок Pester 5, оплаченный двумя итерациями CI**: (а) мок, созданный в
    module scope (`InModuleScope`), живёт до конца файла и перехватывает
    вызовы из ДРУГИХ Describe-блоков — моки `Test-Path`/`New-Item` в V07/V11
    съедали создание каталога стора; добавлены `ParameterFilter` по
    `HK*:*` — файловая система больше не подменяется; (б) метаданные
    оригинального командлета копируются на мок: мок
    `Register-ScheduledTask` биндит `-Settings` типом `CimInstance`, поэтому
    pscustomobject-стабы билдеров падали на биндинге до тела мока; стабы
    заменены синтетическими `CimInstance` классов
    MSFT_TaskAction/Trigger/Settings, маркеры регистрации пишутся фиксированной
    строкой (именованные параметры метадата-верного мока не попадают в `$args`).
  - DNS-тест «apply sets the servers, the probe passes honestly» остался
    красным: probe честно вернул несовпадение на CI-раннере, причины по логу
    не видно (assert печатал только `$false`). Тест усилен диагностикой —
    `Should -BeTrue -Because` теперь печатает матрицу Expected/Actual и
    состояние фейка; разбор — следующая итерация по фактам CI, не по догадкам.
  - **Fallout третьего прогона (run 51, разбор по фактам NUnit-XML с
    ci-report):** оба красных теста — одна причина, доказанная локально на
    том же движке (pwsh 7.6.9 / .NET 10.0.14, что и на обновившемся образе
    windows-latest). Pester 5.7.1 копирует метаданные параметров РЕАЛЬНОГО
    командлета на мок; у `Remove-ItemProperty -Name` и
    `Set-/Get-DnsClientServerAddress -InterfaceAlias` эти параметры
    объявлены `[String[]]`, поэтому скаляр приходит в мок обёрнутым в
    одноэлементный массив. Фейк-состояние получало КЛЮЧИ-МАССИВЫ:
    (а) `network.dns` — `ConvertTo-Json` в диагностике `-Because` на PS 7.6
    (System.Text.Json) запрещает не-строковые ключи словаря —
    `InvalidOperationException: Keys must be strings`; (б) `network.proxy`
    — undo писал `'<unset>'` в теневую запись с массив-ключом, а ассерты
    читали исходную строковую запись и видели до-undo значение `'1'`.
    Лечение — нормализация `[string](@($param)[0])` в телах моков V06/V07
    (и превентивно V11); на PS 7.4 те же моки молча «работали», поэтому
    класс бага вскрылся только первым честным прогоном размаскированных
    admin-тестов на новом образе.
  - Парсер отчёта о падении в ci.yml слеп: XPath искал
    `@result='Failed'`, а писатель NUnit 2.5 у Pester пишет
    `result="Failure"` — отчёты прогонов 47/50/51 показывали
    «failed test cases: 0» при `failures="2"` в том же XML. XPath принимает
    оба написания, имя теста берётся с фолбэком fullname→name, в список
    сьютов попадают только TestFixture-узлы.

## [1.3.0] — 2026-11-03

### Added
- Пакеты функций с зависимостями (№102): группы поверх профилей.
  `Get-DomovoyGroup` читает декларативные JSON-группы (`config/groups/`,
  своя схема), `Invoke-DomovoyGroup` разрешает граф зависимостей
  (post-order DFS): зависимости — раньше зависимых, цикл — честная ошибка
  с полной цепочкой `a -> b -> a`, недостающая зависимость называет
  того, кто её требует. План показывает точный порядок с атрибуцией —
  откуда приехала каждая фича (`features`, `profile:X`, зависимая группа)
  — дубликаты не выбрасываются молча, а попадают в Skipped с именем
  первой причины; чужие риск-потолку фичи и отсутствующие манифесты —
  тоже. `-Apply` создаёт одну точку восстановления на всю группу, ведёт
  каждую фичу через общий конвейер (снимок, пробы, журнал, undo),
  собирает отказы честно и пишет одну запись `group.apply` с порядком и
  счётчиками; под `-WhatIf` не пишется ничего. Поставляются две группы:
  `privacy-essential` (профиль cautious + 3 низкорисковые политики) и
  `home-essentials` (зависимость от первой + профиль standard + proxy-off
  + авто-DoH).
- Явная миграция журнала между версиями схемы (№101): `Get-DomovoyLedgerSchema`
  — только чтение, инвентаризация версий схемы по записям (включая записи
  без поля `schema` и записи, написанные БОЛЕЕ новой версией Домового —
  они честно считаются отдельно, понижение версии никогда не
  предпринимается). `Invoke-DomovoyLedgerMigration` — план по умолчанию и
  вердикты без вранья: `empty`, `already-current` (Apply — честный no-op,
  ни одной записи не появляется), `future-entries` (на Apply — громкий
  отказ), `migration-not-defined` (записи старее есть, правила
  преобразования в этом релизе нет — ничего не меняется, правило приедет
  вместе с релизом, определяющим схему 2). Сам механизм перезаписи готов
  и покрыт тестами: побайтовый бэкап, остановка до первого изменённого
  байта на битой строке, перестройка хеш-цепочки от `genesis` тем же
  контрактом, что у писателя, запись `ledger.migrate` в аудит. Писатель
  журнала теперь берёт версию схемы из одного источника правды
  (`Get-DomovoyLedgerSchemaVersion`).
- Аудит shell-расширений и «Открыть с помощью» (№104, только чтение —
  фундамент №81): `Get-DomovoyShellMenuReport` перечисляет обработчики
  контекстного меню по всем документированным точкам регистрации
  (`*`, AllFilesystemObjects, Directory, Directory\Background, Folder,
  Drive) с CLSID, разрешённым COM-сервером (InprocServer32) и тремя
  честными вердиктами: DLL на диске, CLSID в документированном списке
  Approved, CLSID вообще есть; плюс инвентаризация ассоциаций
  «Открыть с помощью» (OpenWithList/OpenWithProgids по расширениям,
  `-Extension` сужает до одного). Всё — встроенным провайдером реестра,
  без внешних процессов и сети (I4); отсутствующий ключ — пустой ответ,
  а не ошибка.
