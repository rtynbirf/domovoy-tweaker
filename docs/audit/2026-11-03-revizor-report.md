## 3. Сверка с мировыми практиками

### 3.1. Где ДОМОВОЙ УЖЕ ВЫШЕ уровня мировой практики

1. **Журнал состояния с хеш-цепочкой (№103)** — ни один из 7 сопоставимых
   проектов не хранит «что было ДО» в tamper-evident виде. У WinUtil/Sophia/
   Win11Debloat/privacy.sexy твик — событие; у нас — проверяемое состояние.
2. **Per-feature undo как инвариант (I7)** — у Sophia undo-функции существуют
   для части твиков как отдельный код; у ДОМОВОГО отсутствие undo/verify
   запрещает загрузку манифеста вообще.
3. **Дозор дрейфа + opt-in авто-лечение** — реакция на откат твиков после
   Windows Update. В мировом классе аналогов нет.
4. **Проверка эффекта пробами** — честная матрица «прошло/не прошло» вместо
   «скрипт отработал без исключений».
5. **Декларативность + схемы JSON** — манифесты валидируются CI по трём схемам
   (features/profiles/groups), PR на твик — diff данных.
6. **MAJOR-политика SemVer (spec §10)** — формальная заморозка форматов на
   v1.x: журнал, манифесты, хранилище, публичные команды. Уровень зрелости,
   которого нет у сопоставимых скриптовых проектов.
7. **Нулевой сетевой контур (I4)** — принципиально, документированно, тестируемо.
8. **Группы с зависимостями (v1.3)** — топологическая сортировка с честным
   отчётом об атрибуции и отказах; у учителей — плоские «apply all» кнопки.

### 3.2. Где мировой класс впереди (находки, приоритеты)

Приоритеты: **P0** — ломает обещание проекта, **P1** — враньё/протухание
документа, **P2** — инженерный долг, влияющий на доверие, **P3** — гигиена
и эволюция. Каждой находке присвоен номер и пункт в ТЗ.

**P0-1. Каталог манифестов не доезжает до пользователя.**
`release.yml` пакует в zip только `src/Domovoy` + README + LICENSE;
`publish-psgallery` публикует `src/Domovoy` как есть. Резолвер каталога
(`Get-DomovoyFeature.ps1:41-51`) ищет `<repoRoot>/config/features`, потом
`<ModuleBase>/config/features` — второго в артефакте НЕТ. Итог: из zip и из
PSGallery `Get-DomovoyFeature` честно бросает «Feature directory not found»;
работают только манифесты по абсолютным путям через `featureSource`.
Критерий приёмки v0.6.0 («установка одной командой из PSGallery») фактически
не выполнен для каталога. Исправление копеечное и уже внесено этим же
коммитом: `config/` и `schema/` копируются внутрь артефакта во всех трёх
релизных задачах (zip, sign, psgallery).

**P1-2. Протухшие числа в README.** «46 публичных команд» (фактически 51),
«Сейчас: v1.2.0» при выпущенном v1.3.0, «Дальше: v1.3.0». Поправлено этим же
коммитом; механизм недопущения — в ТЗ (§ v1.4, пункт 5).

**P1-3. Молчаливый перенос №77 и №95.** Оба пункта каталога помечены
«v1.2 (запланировано)», v1.2 и v1.3 вышли без них — без честной пометки
переноса, обязательной по собственным правилам проекта (веха v1.1:
«каталог честен: перенесённое помечено»). Поправлено этим же коммитом
(перенос на v1.4 с пометкой). №81 корректно помечен v1.4.

**P1-4. spec.md отстал на три вехи.** Заголовок «версия 0.3.0»; §5.1 —
таблица из 6 op-типов (фактически 10: добавлены scheduler.task, network.dns,
network.proxy, file.timestamp); §8 — таблица 22 команд эпохи v0.5 (фактически
51); нет раздела про группы и миграцию журнала. Техническая спецификация —
заявленный источник правды — сейчас правды не отражает.

**P2-5. Из CI пропала нога PS 5.1.** spec §3: «PowerShell 5.1 и 7+. Оба
обязательны к поддержке». Коммит v0.1 (361d6ea) декларировал «PS 5.1 smoke»;
текущий ci.yml гоняет только `pwsh` (7.x). Хеш-цепочка v1.2 гордится
«одинаково на 5.1 и 7.x» — а CI это не проверяет.

**P2-6. Релиз не ждёт зелёного CI.** Release запускается по тегу независимо
от результата тестов на этом коммите; тег на красном HEAD ушёл бы в релиз.
Мировая практика: гейт на статус тестового воркфлоу перед публикацией.

**P2-7. Из .github выпали community-файлы.** Скаффолд (9082523) содержал
`.github/ISSUE_TEMPLATE/*`, `.github/pull_request_template.md`,
`.github/dependabot.yml`; в текущем дереве их нет (только два workflow).
Отсутствует и `PSScriptAnalyzerSettings.psd1` — анализатор в CI гоняет с
дефолтными настройками, калибровка severity невозможна.

**P2-8. Нет измерения покрытия.** Pester умеет код-коверидж; CI его не
включает, NUnit-артефактов нет (только аннотации на падении). Без числа
«покрыто X%» рост каталога не измеряется.

**P3-9. Supply-chain: actions пинятся тегом, не SHA.** `actions/checkout@v4`
— мировая практика (GitHub Docs «Secure use», политика GitHub от 2025-08-15)
— пин по коммит-SHA + Dependabot/Renovate на обновления.

**P3-10. Мелкая гигиена конвейера:** нет concurrency-группы (параллельные
пуши гоняют CI впустую); нет `.sha256`-ассета рядом с zip (сумма зашита
только в winget-yaml); `Publish-Module` устарел в пользу
Publish-PSResource/PSResourceGet.

**P3-11. Нет обновляемой справки:** HelpInfoUri в psd1 отсутствует, внешней
справки (platyPS) нет; comment-based `.SYNOPSIS` есть у всех 51 команды
(проверено), но глубина `.PARAMETER`/`.EXAMPLE` не гейтится.

**P3-12. Тихий fallback в release.yml:** если секция CHANGELOG для тега не
вырезалась — молча публикуется «Domovoy vX.Y.Z» одной строкой. Пустая секция
должна валить релиз, а не заменяться заглушкой.

**Третий проход — красный CI на первом пуше v1.4.0 и его урок:** прогон №34
уронил тест «on non-Windows it refuses loudly» — и вскрыл находку P1-13:
Pester 5 вычисляет `-Skip` на дискавери, а флаг платформы во ВСЕХ сьютах
определялся в `BeforeAll` (исполняется позже), то есть каждый платформенный
гейт читал неопределённую переменную. Следствие: «non-Windows» тесты
исполнялись и на Windows (падение), а «Windows-only» Describe-блоки —
скипались ВЕЗДЕ, ни разу не гоняясь в CI. В v1.4.0 флаг перенесён на
топ-уровень в двух новых сьютах (V14.Catalog, V14.Shell — E2E №81 впервые
реально исполняются на Windows-раннере); размаскирование остальных четырёх
сьютов — веха v1.4.1 в [ТЗ](2026-11-03-backlog-tz.md). Урок стоит запомнить:
«skipped: N» в CI — это тоже число, которое обязано быть честным.

**Итог раундов CI и релиз:** четыре прогона (34 красный → 37 красный —

winget-манифесты; контрольная сумма скачанного zip свершена `sha256sum -c`
— OK, внутри все 58 манифестов каталога и схема: критерий v0.6.0 «каталог
доезжает до пользователя» проверен живьём.

**Осталось за вехой v1.6** (ждёт владельца): PSGallery-публикация с
