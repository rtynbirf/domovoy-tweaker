# Техническая спецификация ДОМОВОЙ

Версия документа: 0.1.0 · Статус: активный прототип · Обновлён: 2026-11-02

---

## 1. Цель и суть

### 1.1. Суть

ДОМОВОЙ — инструмент управления настройками Windows, в котором каждый твик
является **управляемым состоянием**, а не разовым действием. «Управляемое состояние»
означает: зафиксировано до изменения, записано после, проверяемо в любой момент,
восстановимо по отдельности.

### 1.2. Проблема

Существующие инструменты (включая всех «учителей» — см. `comparison.md`) применяют
настройки как событие. Через месяц пользователь не может ответить на вопросы:
«что именно я менял?», «что из этого пережило обновление Windows?», «как отменить
только одну функцию, не трогая остальные?».

### 1.3. Решение

Четыре контура: Журнал (Ledger), Машина времени (undo по-функционально),
Дозор (детекция дрейфа), Проверка эффекта (верификация пробами).
Подробно — `architecture.md`.

### 1.4. Не-цели

- Не антивирус и не «оптимизатор-ускоритель» с пустыми обещаниями.
- Не система резервного копирования всего ПК (только то, что трогаем сами).
- Не инструмент удалённого/корпоративного принуждения (локальная машина, локальный админ).
- Не замена групповым политикам — наоборот, экспорт в них запланирован (v0.7).

## 2. Термины

| Термин | Значение |
|---|---|
| **Функция (Feature)** | Единица твика с манифестом: id, операции, пробы, откат |
| **Манифест** | JSON-файл декларативного описания функции (`schema/features.schema.json`) |
| **Операция (op)** | Атомарное действие: `registry.set`, `service.startup` (в v0.1) |
| **Проба (probe/verify)** | Проверка фактического состояния, соответствующая операции |
| **Снимок (snapshot)** | Значения ДО применения, восстановимые при undo |
| **Журнал (Ledger)** | Append-only JSONL-файл всех событий изменения состояния |
| **Дрейф (drift)** | Расхождение фактического состояния с зафиксированным ожидаемым |
| **Dry-run** | Показ плана изменений без применения (режим по умолчанию) |

---

## 3. Окружение и требования

- ОС: Windows 10 (2004+) и Windows 11, x64.
- PowerShell: 5.1 (Desktop) и 7+ (Core). Оба обязательны к поддержке.
- Права: чтение каталога функций — любые; `-Apply` и undo — elevated-сессия
  (проверяется `Test-DomovoyAdmin`, а не «повезёт/не повезёт»).
- Кодировки: `.ps1/.psm1/.psd1` — ASCII-only в коде (совместимость PS 5.1);
  JSON — UTF-8; журнал — UTF-8 JSONL.
- Хранилище: `%ProgramData%\Domovoy\`, переопределяется переменной `DOMOVOY_STORE`
  (используется тестами и CI).

## 4. Архитектура верхнего уровня

CLI-first. GUI — отдельный слой не раньше v0.7 (см. `roadmap.md`).
Модуль `Domovoy` не содержит сетевых вызовов вообще — это инвариант I4 (§7).

## 5. Модель данных

### 5.1. Манифест функции

JSON по схеме `schema/features.schema.json`. Обязательные поля:

```text
id          — 'category.object.action', строчные латинские/цифры/точки/дефисы
title       — человекочитаемое название
version     — SemVer версии самой функции
category    — privacy | services | apps | ui | network | maintenance | drivers | security | core
risk        — low | medium | high
description — что делает, одним абзацем
ops[]       — операции применения
undo        — { "mode": "snapshot" } (обязательно; другие режимы — после v0.3)
verify[]    — пробы эффекта (обязательно ≥1)
references[]— ссылки на документацию Microsoft (обязательно, https)
```

Типы операций (v0.2):

| op | поля | обратная операция из снимка |
|---|---|---|
| `registry.set` | `path, name, value, valueType` | восстановление `previousValue`/`previousType` или удаление значения, если его не было |
| `registry.delete` | `path, name` | то же: восстановление прежнего значения с типом или ничего, если значения не было |
| `service.startup` | `name, startupType` | восстановление прежнего типа запуска |
| `service.stop` | `name` | запуск службы, если до твика она была `Running` |

Типы проб (v0.2): `registry.set` (равенство значения), `registry.absent` (значение
отсутствует), `service.startup` (тип запуска), `service.status` (фактический статус).

Планируемые типы операций: `scheduler.task`, `appx.remove`,
`file.attribute`, `service.config`, `profile.export` (см. `roadmap.md`).
**Инвариант расширения:** новый op-тип принимается только вместе с проекциями
probe / snapshot / undo (§6.4).

### 5.2. Снимок

Список записей `{ op, path|name, previousValue, previousType }` — по одной на каждую
операцию манифеста, собранную перед применением.

### 5.3. Журнал (Ledger)

Файл `ledger.jsonl`, по событию на строку:

```json
{"schema":1,"event":"feature.apply","tool":"Domovoy","toolVersion":"0.2.0",
 "timestamp":"2026-11-02T12:00:00.0000000+00:00","featureId":"...","featureVersion":"1.0.0",
 "featureSource":"C:\\path\\to\\manifest.json",
 "snapshot":[...],"verification":{"feature":"...","allPass":true,"results":[...]}}
```

События: `ledger.init`, `feature.apply`, `feature.undo`.

### 5.4. Хранилище

```text
%ProgramData%\Domovoy\
├── ledger.jsonl                 # журнал (append-only)
├── snapshots/<featureId>/<ts>.json   # явные снимки (Backup-DomovoySnapshot)
└── backups/                     # резервные копии файлов (после v0.3)
```

## 6. Алгоритмы

### 6.1. Apply (`Invoke-DomovoyFeature`)

1. Прочитать и провалидировать манифест.
2. Построить план: для каждой операции — текущее значение (реестр) или тип запуска (служба).
3. Нет `-Apply` → вернуть план и завершиться (dry-run по умолчанию).
4. Проверить elevation; без прав — ошибка, ничего не тронуто.
5. Создать точку восстановления (мягко; ограничение ОС — раз в 24 ч).
6. Собрать снимок текущих значений.
7. Выполнить операции по порядку.
8. Прогнать пробы `verify`.
9. Записать событие `feature.apply` в журнал.
10. Любое исключение на шагах 7–8 → частичное применение фиксируется в журнале
    с `verification.allPass = false` и пробрасывается наверх.

### 6.2. Undo (`Undo-DomovoyFeature`)

1. Найти последнее событие `feature.apply` для `featureId` в журнале.
2. Dry-run без `-Apply`: показать снимок, который будет восстановлен.
3. Восстановить каждое значение из снимка (тип включительно; «не было» → удалить).
4. Прогнать пробы; записать событие `feature.undo`.

### 6.3. DriftScan (`Invoke-DomovoyDriftScan`)

1. Из журнала взять последнее `feature.apply` по каждой функции.
2. Для каждой — прогнать пробы.
3. `drifted = есть проба, фактическое значение ≠ ожидаемому`.
4. Отчёт: scanned / drifted / детали по каждой пробе.
5. (v0.4) базовая линия — последний verified-снимок, а не манифест; (v0.6) opt-in авто-лечение.

### 6.4. Verify (`Test-DomovoyEffect`)

Проба → фактическое значение → строковое сравнение с ожидаемым →
`{probe, target, expected, actual, pass}`. Матрица проб возвращается всегда, честный FAIL — норма.

## 7. Инварианты безопасности

| № | Инвариант |
|---|---|
| I1 | Журнал append-only: события не редактируются и не удаляются |
| I2 | Снимок собирается ДО первой операции; без снимка применение запрещено |
| I3 | Dry-run по умолчанию: применение только при явном `-Apply` |
| I4 | Нулевой сетевой контур в модуле (нет `Invoke-WebRequest`/`WebClient`/`curl` в коде) |
| I5 | Elevation проверяется явно; без прав изменения невозможны |
| I6 | Идемпотентность: повторный apply не меняет результат |
| I7 | Манифест без `undo` или `verify` не загружается вообще |

## 8. Интерфейс команд (v0.2)

| Команда | Назначение |
|---|---|
| `Initialize-Domovoy` | создать хранилище и генезис-запись журнала |
| `Get-DomovoyFeature` | каталог функций из манифестов, фильтр по id |
| `Invoke-DomovoyFeature` | план (dry-run) или применение с снимком и записью в журнал |
| `Undo-DomovoyFeature` | откат функции из последнего снимка |
| `Get-DomovoyLedger` | чтение журнала, фильтры по функции/событию |
| `Invoke-DomovoyDriftScan` | скан дрейфа по всем применённым функциям |
| `Test-DomovoyEffect` | пробы эффекта по функции |
| `Backup-DomovoySnapshot` | явный снимок состояния функции в файл |
| `New-DomovoyRestorePoint` | точка восстановления системы (обёртка `Checkpoint-Computer`) |

## 9. Известные ограничения (честно, v0.2)

1. Undo восстанавливает значения и типы, но не удаляет ключи реестра, созданные
   твиком (удаление значений — да, включая восстановление удалённых). Полное undo ключей — v0.3.
2. `service.startup` меняет только тип запуска, не останавливая работающую службу;
   для остановки есть отдельный op `service.stop` (с снимком статуса и запуском при undo).
3. DriftScan сравнивает с ожидаемым из манифеста, а не с последним verified-снимком —
   базовая линия из снимков — v0.4.
4. Точка восстановления ограничена ОС (раз в 24 ч) — фиксируется в журнале.
5. Нет поддержки «пакетов» (профилей из нескольких функций) — v0.4.

## 10. Версионирование и релизы

- SemVer: MAJOR — ломающие изменения формата журнала/манифеста; MINOR — новые
  функции/op-типы; PATCH — исправления.
- Conventional Commits; CHANGELOG.md ведётся с первого релиза.
- Теги `vX.Y.Z` только на `main`; release notes — по CHANGELOG.
