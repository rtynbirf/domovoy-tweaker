# Справочник op-типов и проб ДОМОВОГО

Каждая функция ДОМОВОГО — это манифест (JSON). Каждый op-тип обязан иметь
**четыре проекции** (правило каталога):

| Проекция | Что делает | Когда видна пользователю |
|---|---|---|
| **plan** | строит человеческое описание будущих действий | dry-run (по умолчанию, инвариант I3) |
| **snapshot** | захватывает текущее состояние ДО первой операции | перед apply (инвариант I2) — снимок целиком уходит в журнал |
| **execute** | выполняет изменение | только при явном `-Apply` |
| **undo** | восстанавливает состояние из снимка | `Undo-DomovoyFeature`, по-функционально |

Инварианты, на которые опирается всё ниже: I1 — журнал append-only; I2 —
снимок до операции; I3 — dry-run по умолчанию; I4 — нулевой сетевой контур;
I5 — явная проверка elevation; I6 — идемпотентность (повторный apply не
считается изменением); I7 — манифест без `undo`/`verify` не загружается.

Пробы (`verify`) — отдельный слой: они не «исполняют», а **отвечают на
вопрос, верно ли текущее состояние**. Ответ всегда честный: если механизм
недоступен или значение неизвестно, проба возвращает ошибку или
`<unknown>`, а не «пройдено».

## Op-типы

### `registry.set` — задать значение реестра

- **plan:** путь, имя, новое значение, тип (`DWord`/`String`/`QWord`/`ExpandString`).
- **snapshot:** прежнее значение и его тип; отсутствие значения — тоже состояние.
- **execute:** `New-ItemProperty`/`Set-ItemProperty`, цепочка ключей создаётся при необходимости.
- **undo:** восстанавливает точное прежнее значение **и тип**; если значения
  раньше не было — удаляет его (создание тоже было изменением).

```json
{ "type": "registry.set", "path": "HKLM:\\SOFTWARE\\Policies\\Microsoft\\Windows\\DataCollection",
  "name": "AllowTelemetry", "value": 0, "valueType": "DWord" }
```

Проба-компаньон: `registry.set` (равенство значения).

### `registry.delete` — удалить значение реестра

- **plan:** путь и имя удаляемого значения.
- **snapshot:** прежнее значение и тип (или честная запись «значение отсутствовало»).
- **execute:** `Remove-ItemProperty`; отсутствие значения — не ошибка (идемпотентность I6).
- **undo:** восстанавливает значение и тип; если значения раньше не было —
  не делает ничего.

```json
{ "type": "registry.delete", "path": "HKCU:\\...", "name": "..." }
```

Проба-компаньон: `registry.absent`.

### `service.startup` — тип запуска службы

- **plan:** служба и новый тип запуска (`Disabled`/`Manual`/`Automatic`);
  несуществующая служба честно помечается в плане как `<missing>`.
- **snapshot:** прежний тип запуска.
- **execute:** `Set-Service -StartupType`. Работающую службу модуль сам не
  останавливает — Windows перестаёт запускать отключённую службу сама;
  убивать процессы не наш способ.
- **undo:** возвращает прежний тип запуска.

```json
{ "type": "service.startup", "name": "DiagTrack", "startupType": "Disabled" }
```

Пробы-компаньоны: `service.startup` (тип запуска), `service.status` (состояние).

### `service.stop` — остановка службы без изменения типа запуска

- **plan:** служба и факт остановки.
- **snapshot:** прежнее состояние (`Running`/`Stopped`).
- **execute:** `Stop-Service`; уже остановлена — ничего не делает (I6).
- **undo:** запускает службу только если она была запущена до операции.

```json
{ "type": "service.stop", "name": "..." }
```

Проба-компаньон: `service.status`.

### `appx.remove` — удаление предустановленного UWP-пакета

- **plan:** имя пакета; системно-критичные пакеты отвергаются ещё на плане.
- **snapshot:** факт присутствия пакета и место его установки.
- **execute:** `Remove-AppxPackage` (текущий пользователь — пакеты всех
  пользователей требуют отдельного осознанного манифеста).
- **undo:** пере-регистрирует пакет из его места установки
  (`Add-AppxPackage -Register`); если файлов уже нет — честная подсказка
  документированного источника (Store/winget), сам модуль ничего не
  скачивает (I4).

```json
{ "type": "appx.remove", "name": "Microsoft.GetHelp" }
```

Пробы-компаньоны: `appx.absent` (после apply), `appx.present` (после undo).

### `file.attribute` — атрибуты файла или папки

- **plan:** путь и целевой набор атрибутов.
- **snapshot:** **полный** прежний набор атрибутов объекта.
- **execute:** `Set-ItemProperty`/`Set-Item -Force` (`-Force` обязателен —
  без него PowerShell не видит файлы с атрибутом Hidden; урок v0.3.0).
- **undo:** возвращает полный прежний набор — не «снимает то, что ставили»,
  а восстанавливает состояние целиком.

```json
{ "type": "file.attribute", "path": "C:\\...\\hosts", "attributes": ["ReadOnly"] }
```

Проба-компаньон: `file.attributes` (закрепляет полный набор).

### `scheduler.task` — состояние задачи планировщика

- **plan:** путь и имя задачи, целевое состояние (`Disabled`/`Enabled`).
- **snapshot:** прежнее состояние задачи.
- **execute:** `Disable-ScheduledTask`/`Enable-ScheduledTask` — **только
  состояние**, определения задач никогда не сносятся.
- **undo:** возвращает прежнее состояние.

```json
{ "type": "scheduler.task", "taskPath": "\\Microsoft\\Windows\\...", "taskName": "...", "state": "Disabled" }
```

Проба-компаньон: `scheduler.taskState`.

### `network.dns` — DNS-серверы адаптеров

- **plan:** адаптеры (`"*"` = все подключённые) и список серверов.
- **snapshot:** прежние списки DNS **по каждому адаптеру**; пустой список
  адаптера = «адаптер на DHCP-умолчаниях».
- **execute:** `Set-DnsClientServerAddress`; адаптер пропадает из плана,
  если он не подключён (честный план, а не «*» на бумаге).
- **undo:** восстанавливает прежний список адаптеру; снапшот с пустым
  списком возвращает адаптер к DHCP-умолчаниям
  (`-ResetServerAddresses`).

```json
{ "type": "network.dns", "interfaceAlias": "*", "servers": ["1.1.1.1", "1.0.0.1"] }
```

Проба-компаньон: `network.dns` (список серверов адаптера; селектор `"*"`
агрегирует и честно помечается `<unknown>` в отчёте «что изменилось»).

### `network.proxy` — WinINET-прокси текущего пользователя

- **plan:** режим (`off` — отключить прокси; `server` — явный сервер,
  опционально `bypassLocal` → `ProxyOverride = <local>`; `pac` — URL скрипта
  автоконфигурации).
- **snapshot:** точная тройка `ProxyEnable`/`ProxyServer`/`AutoConfigURL`.
- **execute:** запись соответствующих значений
  `HKCU:\...\Internet Settings`; режим `off` кладёт `ProxyEnable = 0`, не
  стирая сервер.
- **undo:** восстанавливает тройку целиком; ненастроенный ранее прокси
  остаётся ненастроенным — не «пересоздаётся выключенным».

```json
{ "type": "network.proxy", "mode": "server", "proxyServer": "proxy.local:3128", "bypassLocal": true }
```

Проба-компаньон: `network.proxy` (закрепляет точную тройку; отсутствие
значения фиксируется как `<unset>`, а не как пустая строка).


### `file.timestamp` — штампы времени файла или папки

- **plan:** текущая тройка штампов (`creation`/`lastWrite`/`lastAccess`,
  UTC, формат `o`); в колонке «новое» незапрошенные поля помечены
  `<keep>` — они остаются без изменений.
- **snapshot:** точная тройка штампов; отсутствие пути фиксируется как
  `<missing>` (и отменой восстанавливается как отсутствие, а не «сегодня»).
- **execute:** установка запрошенных штампов как UTC-моментов
  (`AssumeUniversal` для строк без смещения; сравнение — мгновение, не
  написание). Работает и для файлов, и для папок; скрытые объекты видны
  через `-Force` (урок `file.attribute`). Несуществующий путь валит apply,
  если в манифесте не заявлен `allowMissing`.
- **undo:** восстанавливает каждый запрошенный штамп из снимка.

```json
{ "type": "file.timestamp", "path": "C:\\Users\\me\\note.txt", "creation": "2024-01-15T10:30:00Z", "lastWrite": "2024-01-15T10:30:00Z" }
```

Проба-компаньон: `file.timestamp` (сравнивает мгновения закреплённых
полей; незакреплённые поля помечаются `<any>` — «размерность не
пинится», как в `network.proxy`).

### `shell.handler.remove` — убрать конкретный обработчик контекстного меню (№81)

- **plan:** путь ключа `{hive}:\Software\Classes\{class}\shellex\ContextMenuHandlers\{handler}`
  и его текущее значение по умолчанию (`<missing>`, если ключа нет).
- **snapshot:** ДЕРЕВО ключа целиком (Get-DomovoyRegKeyTree: подключи,
  значения, типы) — не только CLSID по умолчанию; отсутствие ключа
  фиксируется честно и отменой восстанавливается как отсутствие.
- **execute:** удаляет ровно этот ключ обработчика. Approved-список,
  CLSID-регистрация и чужие обработчики не трогаются (аудит №104 —
  фундамент: пользователя сначала показывает, потом предлагает убрать).
- **undo:** пересоздаёт точное дерево ключа из снимка (Restore-DomovoyRegKeyTree);
  если обработчика ДО не было — восстанавливает отсутствие.

```json
{ "type": "shell.handler.remove", "hive": "HKCU", "class": "Directory", "handler": "Sharing" }
```

Проба-компаньон: `shell.handler.absent` (ключ обработчика должен
отсутствовать; наличие — честный FAIL).

### `shell.handler.block` — заблокировать shell-расширение по CLSID (№81)

- **plan:** текущее значение CLSID в документированном Blocked-списке
  `HKLM:\...\Shell Extensions\Blocked` (`<unset>`, если не заблокирован).
- **snapshot:** точное прежнее значение (или `<unset>`).
- **execute:** записывает CLSID в Blocked-список с `reason` из манифеста
  (или `<blocked>`). Регистрация расширения НЕ трогается — это задокументированный
  механизм самой Windows, обратимый по построению.
- **undo:** восстанавливает прежнее значение или удаляет запись, если
  её не было.

```json
{ "type": "shell.handler.block", "clsid": "{00000000-0000-0000-0000-000000000000}", "reason": "домашнее решение по результату аудита №104" }
```

Проба-компаньон: `shell.handler.blocked` (CLSID присутствует в Blocked-списке).

### `shell.openwith.remove` — убрать подсказку из меню «Открыть с помощью» (№81)

- **plan:** запись `{extension}` в per-user `FileExts\{kind}`: для
  `OpenWithList` — буква, чьи данные совпали с `entry`; для
  `OpenWithProgids` — значение по имени `entry` (`<absent>`, если записи нет).
- **snapshot:** точные удалённые буквы с данными и точная строка `MRUList`
  (для OpenWithList) либо тип и данные значения (для OpenWithProgids).
- **execute:** удаляет только указанную подсказку; ассоциация (`UserChoice`)
  и чужие записи не трогаются.
- **undo:** восстанавливает буквы с точными данными и точную `MRUList`
  (или её отсутствие); для ProgIds — точный тип и данные (нерегламентируемый
  тип честно восстанавливается как String с предупреждением).

```json
{ "type": "shell.openwith.remove", "extension": ".txt", "kind": "OpenWithList", "entry": "legacyapp.exe" }
```

Проба-компаньон: `shell.openwith.absent` (подсказки для entry больше нет;
для OpenWithList ищет по данным букв, MRUList не считается записью).

## Пробы

| Тип | Отвечает на вопрос | Честность |
|---|---|---|
| `registry.set` | значение равно ожидаемому (с точностью до типа)? | отсутствие значения — честный ответ «нет», а не `0` |
| `registry.absent` | значения действительно нет? | |
| `service.status` | служба в ожидаемом состоянии (`Running`/`Stopped`)? | |
| `service.startup` | тип запуска службы ожидаемый? | |
| `appx.present` | пакет установлен? | для отсутствующего пакета отвечает «нет», не ошибкой |
| `appx.absent` | пакет действительно удалён? | |
| `file.attributes` | набор атрибутов объекта точно такой, как ожидается? | сравнивает **полный** набор, а не вхождение |
| `scheduler.taskState` | задача в ожидаемом состоянии? | несуществующая задача — ошибка, а не «пройдено» |
| `network.dns` | список серверов адаптера совпадает? | селектор `*` агрегирует адаптеры и помечается `<unknown>` в отчёте изменений |
| `network.proxy` | тройка ProxyEnable/ProxyServer/AutoConfigURL точная? | отсутствующее значение = `<unset>` |
| `file.timestamp` | запрошенные штампы времени совпадают с ожидаемыми (мгновение, а не написание)? | незапрошенные поля = `<any>`; отсутствующий путь — честный FAIL |
| `shell.handler.absent` | ключ обработчика контекстного меню действительно отсутствует? | наличие Approved-записи или CLSID не проверяется — только точный ключ |
| `shell.handler.blocked` | CLSID присутствует в документированном Blocked-списке? | отсутствие записи = «не заблокирован», а не ошибка |
| `shell.openwith.absent` | подсказки «Открыть с помощью» для entry больше нет? | для OpenWithList ищет по данным букв; MRUList записью не считается |

Гейт CI: ни один тип пробы ни одного манифеста не может остаться без
реализации в `Test-DomovoyEffect` — покрытие проб 100%, проверяется
тестом `every verify probe type is implemented in Test-DomovoyEffect`.

## Как это сходится в контур

`Invoke-DomovoyFeature` (dry-run → `-Apply`): план → снимок → исполнение →
пробы → событие журнала → результат с «что реально изменилось»
(значение ДО из снимка, ПОСЛЕ из проб, флаг `Changed`; идемпотентный
повтор даёт `Changed = false`).

`Undo-DomovoyFeature`: dry-run показывает снимок из журнала → `-Apply`
восстанавливает состояние и пишет `feature.undo`.

С v1.2 журнал стал tamper-evident (№103): каждая новая запись несёт `hash`
(SHA-256 своей канонической формы — сериализатор с сортировкой ключей
ordinal, свой, детерминированный между Windows PowerShell 5.1 и 7.x) и
`prevHash` (хеш предыдущей записи или `genesis`). `Test-DomovoyLedgerIntegrity`
проходит журнал целиком: старые до-v1.2 записи честно считаются `unchained`
(это не ошибка), переписанная или переставленная запись ломает цепочку
на своей строке. Формат аддитивен: schema = 1, SemVer MAJOR-политика
соблюдена.

Дозор (`Invoke-DomovoyDriftScan`) сверяет текущее состояние проб с
verified-базовой линией журнала; авто-лечение (`Invoke-DomovoyAutoHeal`,
opt-in) лечит дрейф ре-apply'ом манифеста, оставляя дрейф-состояние
undo-ным.
