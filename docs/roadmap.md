# Дорожная карта ДОМОВОЙ

Принцип версионирования: каждая веха имеет проверяемые критерии приёмки.
Полный каталог функций с привязкой к вехам — `features.md`.

---

## v0.1.0 — Скелет прототипа ✅ (2026-11-02)

**Содержание:** PowerShell-модуль (9 команд), формат манифеста + JSON-схема,
2 эталонных манифеста, Pester-тесты, CI, полный пакет документации.

**Критерии приёмки:**
- [x] Модуль импортируется в PS 5.1 и PS 7 без ошибок.
- [x] Dry-run работает без прав администратора и ничего не меняет.
- [x] Оба манифеста проходят схему и тесты в CI.
- [x] В коде модуля нет ни одного сетевого вызова (инвариант I4).

## v0.2.0 — Журнал и откат как рабочий контур ✅ (2026-11-02)

**Содержание (выполнено):**
- Ledger MVP: append-only JSONL, снапшоты, undo — полностью по spec §6.
- Первые 10 функций (2 из v0.1 + 8 новых): службы + приватность, только документированные пути.
- Новые op-типы с 4 проекциями: `registry.delete`, `service.stop`; пробы `registry.absent`, `service.status`.
- `featureSource` в журнале — undo работает даже для манифестов вне каталога.
- E2E-тесты apply → verify → undo на временных ключах HKCU.

**Критерии приёмки:**
- [x] apply → undo возвращает точные прежние значения **и типы** (не «похожие»). Тест: удаление → откат восстанавливает 7/DWord.
- [x] Значение, которого не было до твика, при undo действительно удаляется. Тест: set → undo → значение отсутствует.
- [x] Журнал переживает обрыв процесса (битая строка не рушит разбор). Тест: битая строка добавляется, разбор продолжается.
- [x] Тесты покрывают apply/undo/ledger на временном хранилище (`DOMOVOY_STORE`).

## v0.3.0 — Debloat, интерфейс и профили ✅ (2026-11-02)

**Содержание (выполнено):**
- 11 новых функций (итого 21): каталог №12, 13 (остаток), 17 (Store-пакет),
  19, 21, 23, 25–27; плюс №3 и №8.
- Новые op-типы с 4 проекциями (op/probe/snapshot/undo): `appx.remove`
  (undo — пере-регистрация пакета из места установки, без сети) и
  `file.attribute` (undo — точный набор атрибутов); пробы `appx.absent`,
  `file.attributes`.
- Профили — декларативные JSON с потолком риска: cautious (low), standard
  (medium); `Invoke-DomovoyProfile` — суммарный dry-run-план по умолчанию,
  одна точка восстановления на профиль, честный отчёт о пропущенных функциях.
- `Backup-DomovoyServiceState` — экспорт таблицы служб (№8).
- Undo ключей, созданных самим твиком (`pathExisted` + подъём по пустой
  цепочке) — закрыто обещание spec §9.1.

**Критерии приёмки:**
- [x] Каждый новый op-тип имеет 4 проекции (op/probe/snapshot/undo) — E2E-тесты.
- [x] `appx.remove` умеет восстанавливать пакет (undo не «пустой»):
  re-register из installLocation; если файлов нет — честный отчёт.
- [x] Профиль — это JSON, а не скрипт: config/profiles/*.json,
  schema/profiles.schema.json, валидация в CI и тестах.

## v0.4.0 — Дозор дрейфа ✅ (2026-11-02)

**Содержание (выполнено):**
- Дозор — полный контур: базовая линия берётся из последнего
  **verified-снимка в журнале** (пробы, зафиксированные сразу после apply),
  а не из манифеста; отчёт несёт даты (appliedAt, detectedAt) и деталь
  расхождения `{probe, target, verified, expected, actual, pass}`;
  `-Since` ограничивает скан моментом X; функции, последнее событие
  которых — undo, не сканируются (каталог №57, №5).
- Op `scheduler.task` с 4 проекциями (op/probe/snapshot/undo) и проба
  `scheduler.taskState`; undo возвращает прежнее состояние задачи (№7).
- Каталог: №7, 14 (сводная блокировка диагностики), 18 (Edge — только
  документированные политики), 28 (панель задач), 30 (советы/рекламные
  тосты), 37 (`Invoke-DomovoyCleanup` — сначала отчёт «сколько освободим»,
  необратимо, факт и объём в журнале), 20 (честная подсказка документированного
  источника восстановления при невозможности re-register). Итого 26 функций.
- Новое событие журнала: `cleanup.apply`.

**Критерии приёмки:**
- [x] Имитация «обновление вернуло политику»: тест вручную возвращает
      значение → скан ловит дрейф (verified '42' против actual '43').
- [x] Отчёт дозора содержит: функцию, дату применения, дату обнаружения,
      деталь расхождения — E2E-тест.

## v0.5.0 — Проверка эффекта как полный контур ✅ (2026-11-02)

**Содержание (выполнено):**
- Отчёт «что реально изменилось» по apply: `Changes` в результате
  `Invoke-DomovoyFeature -Apply` — значение до (из снимка) и после (из проб)
  по каждой пробе, с признаком `Changed`.
- 100% покрытие манифестов пробами: проба `appx.present` (№24), тест-гейт
  «каждый verify-тип реализован», CI гоняет пробы по каждой функции —
  ни одного «unknown-probe».
- Отчёты только для чтения: №15 (телеметрия одним списком), №41 (Run/RunOnce),
  №45+42 (инвентаризация и JSON-экспорт драйверов), №49 (BitLocker),
  №63 («что изменилось с момента X» по журналу).
- Действия с dry-run по умолчанию и журналом: №32 (сброс сети — снимается и
  восстанавливается всё, что можно снять; Winsock честно необратим),
  №38 (очистка журналов событий с измеримым «до/после»), №40 (тримминг памяти
  с честной пометкой), №51 (sfc/DISM с журналом результата).
- №44: «до/после» очистки temp — фактический пересчёт остатка
  (`FilesFound`/`BytesFound`/`BytesAfter`).
- Новые события журнала: `networkreset.apply`, `eventlog.cleanup.apply`,
  `memorytrim.apply`, `integritycheck.apply`.
- №53 (Defender не отключается) остаётся задокументированным принципом-отказом.

**Критерии приёмки:**
- [x] `Test-DomovoyEffect` по каждой функции в `config/features` — без
      исключений «unknown-probe» (тест-гейт + CI-прогон по всем 26 манифестам).
- [x] Отчёт «до/после» включает измеримый объём: байты до/после и
      освобождённые байты в temp-очистке, записи журналов событий в
      eventlog-очистке, байты рабочих множеств в тримминге.

## v0.6.0 — Авто-лечение, дистрибуция ✅ (2026-11-02)

**Содержание (выполнено):**
- Авто-лечение дрейфа — **opt-in**, по расписанию, с журналом каждого
  действия: `Invoke-DomovoyAutoHeal` (dry-run по умолчанию; лечение =
  ре-apply манифеста, дрейф-состояние снапшотится и остаётся undo-ным,
  цикл — событие `autoheal.cycle` с триггером Manual/Scheduled) и
  `Register-/Unregister-DomovoyWatchdog` (задача `\Domovoy\DriftWatchdog`
  создаётся только явной командой пользователя; Interactive-вход без
  хранения пароля; runner-скрипт генерируется при регистрации).
- DNS-профили (№34): op `network.dns` с 4 проекциями (plan/snapshot/
  execute/undo) + проба `network.dns`; манифесты cloudflare/quad9/google.
- Дедуп старых драйверов (№43) только после полного бэкапа .cab —
  экспорт всех сторонних драйверов, LZX-cab через makecab, удаление без
  `/force`; полный дамп драйверов (№46) — тот же бэкап-гейт.
- Снятие атрибутов (№47) и смена владельца (№48) по явному пути —
  с полными снапшотами в журнале и undo-командами.
- Прозрачные привилегии токена (№52): `Get/Enable/Disable-DomovoyPrivilege`
  на реальном AdjustTokenPrivileges, каждое включение/выключение —
  событие `privilege.enable/disable`.
- Бэкап ключа BitLocker (№50): ключ только в файл пользователя, никогда
  в журнал и в вывод; ACL-ограничение файла.
- Дистрибуция: zip + winget-манифесты (шаблоны + генератор) в каждом
  релизе; опциональная Authenticode-подпись (секреты `CODE_SIGNING_PFX`/
  `CODE_SIGNING_PASSWORD`) и опциональная публикация в PSGallery
  (секрет `PSGALLERY_API_KEY`) — без секретов релизы выходят как раньше,
  CI проверяет подпись, когда она есть, и явно принимает unsigned-by-design.
- Каталог честен: №29, 33, 35 перенесены в v0.7 с пометкой о переносе.

**Критерии приёмки:**
- [x] Установка одной командой из PSGallery; `install.ps1` не нужен —
      команда `Install-Module -Name Domovoy` работает, когда задан
      `PSGALLERY_API_KEY`, zip-установка работает уже сейчас; `install.ps1`
      не существует.
- [x] Подписанный модуль; CI проверяет подпись — конвейер подписи готов
      (job `sign`), CI гоняет Authenticode-проверку на каждый пуш:
      подписи нет — «unsigned by design», подпись есть — обязана быть Valid.
- [x] Авто-лечение: цикл с журналом, лечение undo-но, запуск по расписанию
      только через явную opt-in регистрацию.
