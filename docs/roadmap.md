# Дорожная карта ДОМОВОЙ

Принцип версионирования: каждая веха имеет проверяемые критерии приёмки.
Полный каталог функций с привязкой к вехам — `features.md`.

---

## v0.1.0 — Скелет прототипа ✅ (2026-11-02)

**Содержание:** PowerShell-модуль (9 команд), формат манифеста + JSON-схема,
2 эталонных манифеста, Pester-тесты, CI, полный пакет документации.

**Критерии приёмки:**
- [x] Модуль импортируется в PS 5.1 и PS 7 без ошибок.
- [x] Dry-run работает без прав администратора и ничего не меняет.
- [x] Оба манифеста проходят схему и тесты в CI.
- [x] В коде модуля нет ни одного сетевого вызова (инвариант I4).

## v0.2.0 — Журнал и откат как рабочий контур

**Содержание:**
- Ledger MVP: append-only JSONL, снапшоты, undo — полностью по spec §6.
- Первые 10 функций (каталог №1–8, 9, 16): службы + телеметрия.
- Новые op-типы: `registry.delete`, `service.stop`.

**Критерии приёмки:**
- apply → undo возвращает точные прежние значения **и типы** (не «похожие»).
- Удалённое при undo значение, которого не было до твика, действительно удаляется.
- Журнал переживает обрыв процесса (битая строка не рушит разбор).
- Тесты покрывают apply/undo/ledger на временном хранилище (`DOMOVOY_STORE`).

## v0.3.0 — 30+ функций и профили

**Содержание:**
- Каталог №17–31: debloat (OneDrive, UWP-пакеты), интерфейс.
- Новые op-типы: `appx.remove` (с восстановлением из Store-источников),
  `file.attribute`.
- Профили: осторожный / стандартный — декларативные пакеты функций.
- Dry-run-отчёт по профилю: суммарный план до подтверждения.

**Критерии приёмки:**
- Каждый новый op-тип имеет 4 проекции (op/probe/snapshot/undo) — правило §6 архитектуры.
- `appx.remove` умеет восстанавливать пакет (undo не «пустой»).
- Профиль — это JSON, а не скрипт.

**Содержание:**

**Критерии приёмки:**

- Отчёт дозора содержит: функцию, дату применения, дату обнаружения, деталь расхождения.
