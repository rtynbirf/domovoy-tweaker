# Полный нумерованный каталог функций ДОМОВОЙ

Легенда статуса: `✅ vX.Y` — реализовано в вехе · `vX.Y` — запланировано ·
`отказ` — сознательно не делаем (и почему).

Колонка «истоки» показывает, какой механизм из Modern Tweaker 2.0/3.0
(реверс-инжиниринг — `analysis/modern-tweaker-case-study.md`) эта функция
переосмысляет. Имена в кавычках — восстановленные символы из бинарников.

## I. Службы

1. **Отключение служб телеметрии и диагностики** — тип запуска → Disabled.
   *истоки:* 2.0 `OpenSCManager`/`ChangeServiceConfig`/`OpenService`/`QueryServiceConfig`. **✅ v0.1** (эталонный манифест `services.diagtrack.disabled`).
2. **Управление любой службой через манифест** — включить/выключить/вручную, только документированные службы.
   *истоки:* тот же слой. **✅ v0.2** (DiagTrack, dmwappushservice, RemoteRegistry).
3. **Профили служб** («минимум», «безопасный стандарт») — декларативные пакеты.
   *истоки:* 2.0 `StopDef`/`StartDef`/`DefKill`/`Defdop` — но без «убить Defender», см. №53. **✅ v0.3** (профили cautious/standard — JSON с потолком риска).
4. **Восстановление службы к состоянию до твика** — из снимка, с типом запуска и зависимостями.
   *истоки:* 2.0 `ServiceDepend`/`dependService`/`delDepend` — зависимости учитываем, но не «сносим». **✅ v0.2** (тип запуска; остановленная твиком служба возвращается в Running при undo).
5. **Дозор служб** — контроль типа запуска после обновлений Windows.
   *истоки:* ничто; это наш контур. **✅ v0.4** (контур дозора: тип запуска служб сверяется с verified-базовой линией из журнала).
6. **Журнал изменений служб** — каждое переключение в Ledger.
   *истоки:* ничто. **✅ v0.2** (append-only JSONL, устойчив к битой строке).
7. **Отключение задач планировщика, связанных с телеметрией** — op `scheduler.task`.
   *истоки:* частично 2.0 (реестровые пакеты трогали задачи). **✅ v0.4** (`scheduler.telemetry-tasks.disabled` — Compatibility Appraiser, CEIP; только состояние задачи, без сноса определений).
8. **Экспорт текущей конфигурации служб** — снимок всей таблицы служб в файл.
   *истоки:* идея экспорта из 2.0 `Exportext`/3.0 `Exportdrv`. **✅ v0.3** (`Backup-DomovoyServiceState` — JSON в хранилище).

## Что сознательно НЕ войдёт (уроки из кейс-стади)

| Отказано | Почему | Истоки |
|---|---|---|
| Запуск внешних скриптов/бинарников, скачанных в рантайме | нулевой сетевой контур (I4) | 2.0 `WebClient.DownloadFile`/`DownloadString` + `RemoteCertificateValidationCallback` (отключение проверки TLS-сертификатов) |
| «Убить все процессы» одним списком | слишком широкая нога для такой силы | 2.0 `KillThemAll`/`GetProcessesByName`/`Kill`/`Terminate` |
| Тихая очистка журналов без следа | очистка сама становится событием (№38) | 2.0 `SysLog`/`ClearLog` |
| Отключение проверки сертификатов TLS | никогда | `RemoteCertificateValidationCallback`/`ServicePointManager` |
| Озвучка и «красивости» поверх системных операций | интерфейс — инструмент, не шоу | 2.0 `SpeechSynthesizer`, 3.0 `ScreenBlocker` |
| Обфускация собственного кода | открытость — принцип | SmartAssembly 8.2 (2.0), koi-protector (3.0) |
